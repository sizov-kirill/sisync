# sisync

Небольшая CLI для синхронизации выбранных файлов между двумя Mac через Git. Один YAML, две команды: `sisync update` и `sisync cron start`.

## Установка

Нужны Git, Python 3.10+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Из каталога этого проекта:

```sh
uv tool install .
```

Если каталог инструментов uv ещё не в `PATH`, выполните `uv tool update-shell` и откройте новый терминал. После изменения исходников переустановите инструмент: `uv tool install --force .`.

Создайте отдельный GitHub-репозиторий для конфигов; он может быть пустым. Настройте обычный доступ Git на чтение и запись по SSH или HTTPS, а также `git config --global user.name` и `user.email`. sisync использует эти настройки. Для cron доступ должен работать без интерактивных запросов.

## Первый компьютер

```sh
mkdir -p ~/.sisync
cp sisync.config.example.yaml ~/.sisync/sisync.config.yaml
```

Укажите свой репозиторий и нужные файлы:

```yaml
repo-link: https://github.com/YOUR_USER/dotfiles.git
cron: "*/5 * * * *"
files:
  zshrc:
    repo-path: shell/zshrc
    machine-path: ~/.zshrc
  espanso-config:
    repo-path: espanso/default.yml
    machine-path: ~/Library/Application Support/espanso/config/default.yml
```

`repo-path` — относительный путь внутри репозитория; `machine-path` — абсолютный путь или путь от `~/`. Для SSH можно указать `git@github.com:YOUR_USER/dotfiles.git`. Пустой список правил записывается как `files: {}`.

```sh
sisync update
sisync cron start
```

Первая команда отправит конфиг и файлы, которых ещё нет в репозитории. Вторая установит задание каждые пять минут. В публичном репозитории содержимое всех этих файлов, включая сам YAML, будет общедоступно.

## Новый компьютер

Установите sisync и настройте Git. Сначала скачайте **полный актуальный** `sisync.config.yaml` из корня репозитория в `~/.sisync/sisync.config.yaml`. Например, для публичного репозитория с веткой `main`:

```sh
mkdir -p ~/.sisync
curl --fail --location \
  https://raw.githubusercontent.com/YOUR_USER/dotfiles/main/sisync.config.yaml \
  -o ~/.sisync/sisync.config.yaml
sisync update
```

Один `update` разложит отсутствующие файлы по нужным местам и создаст родительские каталоги. Если файл уже существует, применяется обычное сравнение дат: его локальная версия тоже может быть отправлена в репозиторий. Для автоматической синхронизации на новом Mac отдельно выполните `sisync cron start`.

Конфиг обязателен для любой команды, включая `--help`. Команды автоматической первоначальной настройки в этой версии нет.

## Добавление и изменение файлов

**Добавить файл:** создайте его, добавьте правило в `~/.sisync/sisync.config.yaml`, выполните `sisync update`. На другом Mac следующий `update` сначала получит новый конфиг, затем сам файл.

**Изменить файл:** редактируйте его по обычному `machine-path`; затем выполните `sisync update` или дождитесь cron. То же относится к редактированию самого YAML.

**Перестать синхронизировать:** удалите правило из YAML. Файлы на диске и в истории Git останутся; удаления не распространяются автоматически.

## Как выбирается версия

Каждый запуск получает свежее состояние ветки по умолчанию; для пустого репозитория создаётся `main`. Первым синхронизируется корневой `sisync.config.yaml`, затем правила из получившегося конфига в порядке YAML.

| Состояние | Действие |
| --- | --- |
| Содержимое совпадает | Ничего не менять, независимо от дат |
| Файл есть только с одной стороны | Скопировать на другую сторону |
| Локальный `mtime` новее | Commit + push локального файла |
| Дата последнего коммита этого пути новее | Скачать файл, установить ему `mtime` этого коммита |
| Разное содержимое, одинаковые даты | Остановиться с ошибкой |
| Файл отсутствует с обеих сторон | Остановиться с ошибкой |

Сравниваются целые Unix-секунды и дата коммиттера, а не дата автора. Для разрешения равенства дат сохраните выбранную локальную версию после времени удалённого коммита и повторите `update`.

Это именно выбранное правило дат: поздний commit старого содержимого может перезаписать более свежую по смыслу правку. При независимом редактировании на двух Mac побеждает дата, слияния нет; важны правильные часы. Загруженные версии сохраняются в истории Git, но локальная правка, перезаписанная до отправки, в историю не попадёт.

Каждый отправляемый файл получает отдельный commit. При ошибке запуск останавливается; уже выполненные операции остаются. Отклонённый push не обходится через force push: повторный `update` заново получает удалённое состояние. Одновременные запуски на одном Mac блокируются.

## Cron

`sisync cron start` добавляет или заменяет собственный блок `# BEGIN SISYNC` … `# END SISYNC`, сохраняя остальные задания. Повторный запуск не создаёт дублей. После изменения поля `cron` выполните команду заново **на каждом Mac** — `update` расписание не меняет.

Лог: `~/.sisync/sisync.log`. Для отключения удалите блок SISYNC через `crontab -e`. Расписание работает в локальном часовом поясе компьютера. Во время сна ноутбука задания не выполняются; после пробуждения можно вызвать `sisync update` вручную. `"* * * 5 *"` означает каждую минуту в мае, а каждые пять минут — `"*/5 * * * *"`.

## Границы первой версии

- Только обычные файлы; каталоги и символические ссылки не поддерживаются. Файлы внутри каталога перечисляются отдельно.
- `repo-link` нельзя автоматически сменить удалённым конфигом. Перенос репозитория выполняется вручную на обоих Mac.
- При скачивании права существующего файла сохраняются; новые создаются с `600` или `700` для исполняемых файлов. Изменение только прав доступа не синхронизируется.
- Приложения не перезапускаются. Например, настройки zsh применятся в новой оболочке.

```sh
uv run python -m unittest discover -s tests -v
```

Тесты используют временные домашние каталоги, локальный bare Git-репозиторий и подставную команду `crontab`. Пользовательские файлы, настоящий crontab и GitHub не затрагиваются.
